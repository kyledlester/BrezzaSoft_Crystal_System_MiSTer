# ADChips SE3208 (EISC) — behaviour implemented by the core

References: MAME `se3208.cpp` (ElSemi) at c2334733 — normative; ADChips "SE3208 Instruction Set Quick Reference
Card" (2006, se3208_quick_ref_060424.pdf, adc.co.kr) — consistent with MAME on every point it covers (operand
order, flags per instruction, MUL updates only V, all immediates signed except shifts/SET/CLR/SWI/HALT).

## Programmer's model

* `R0-R7` (32-bit), `PC`, `SP`, `ER` (extension register), `SR`.
* `SR` bits: C `0x0080`, Z `0x0040`, S `0x0020`, V `0x0010`, M `0x0200`, E `0x0800` (ER valid), AUT `0x1000`
  (vectored interrupts), ENI `0x2000` (interrupt enable), NMI `0x4000`.
* Reset: `R*=0, SP=0, ER=0, SR=0, PC=read32(0x00000000)`.
* 16-bit instructions at even addresses, little-endian 32-bit data space.

## Extended immediates (EISC)

`LERI imm14`: if E is clear, `ER = sext14(imm)`, else `ER = (ER << 14) | imm`; then E is set. The following
instruction that takes an immediate builds it as `(ER << n) | (imm & (2^n - 1))` with `n = 4` for loads/stores/
ALU-immediate/LDI/LEA and `n = 8` for branches/CALL/LEASPTOSP; **the scaled immediate is truncated to n bits**
(e.g. `LD (%R1, 0x7c)` with E set uses `(ER<<4) | (0x7c & 0xf)`). That instruction clears E.

E is **not** cleared by: register-form ALU ops (ADD ADC SUB SBC AND OR XOR CMP TST NEG MOV), MULS clears it,
PUSH, POP (POP SR restores it), SET, CLR, HALT, MVTC, MVFC and an undecodable opcode. An interrupt clears E after
pushing SR (so E survives through the handler's `POP SR`).

## Encoding (bits 15..0) — transcribed from `decode_op`

| Pattern | Instruction | Operands |
| --- | --- | --- |
| `00 ooo ddd iii fffff` | LDB/LDS/LD/LDBU/STB/STS/ST/LDSU (o = 0..7) | `rd=[10:8] ri=[7:5]` (0 = zero base), `off=[4:0]` ×1/×2/×4 |
| `01 iiiiiiiiiiiiii` | LERI | imm14 |
| `10 000 ddd iiiiiiii` | LDSP | `rd=[10:8]`, off8×4 |
| `10 001 ddd iiiiiiii` | STSP | |
| `10 010 mmmmmmmmmmm` | PUSH | mask: b10 PC, b9 SR, b8 ER, b7..0 R7..R0 (pushed high to low) |
| `10 011 mmmmmmmmmmm` | POP | popped R0..R7, ER, SR, PC (low to high) |
| `10 1x/11x iiii ppp sss ddd` (`[13:11]≥4`) | `[8:6]`: ADDI ADCI SUBI SBCI ANDI ORI XORI, 7 → `[2:0]`: CMPI TSTI LEATOSP LEAFROMSP | imm4 `[12:9]`, src `[5:3]`, dst `[2:0]` |
| `11 00 sss ppp aaa ddd` | `[8:6]`: ADD ADC SUB SBC AND OR XOR, 7 → `[2:0]`: CMP TST MOV NEG | src2 `[11:9]`, src1 `[5:3]`, dst `[2:0]` (MOV/NEG: dst `[11:9]`) |
| `11 01 cccc iiiiiiii` | JNV JV JP JM JNZ JZ JNC JC JGT JLT JGE JLE JHI JLS JMP CALL | off8 ×2, PC-relative to the instruction |
| `11 10 1 ddd iiiiiiii` | LDI | `rd=[10:8]`, imm8 |
| `11 10 0 1 ooo sss iiii` | `[9:7]`: 0 LDBSP 1 LDSSP 3 LDBUSP 4 STBSP 5 STSSP 7 LDSUSP | `rs/rd=[6:4]`, off4 |
| `11 10 0 0 1 x iiiiiiii` | LEASPTOSP | off8×4 (sext10) |
| `11 10 0 0 0 0 oooo rrrr` | `[7:4]`: 0 EXTB 1 EXTS 8 JR 9 CALLR 10 SET 11 CLR 12 SWI 13 HALT | `[3:0]` |
| `11 11 0xx …` | `[4:3]`: ASR LSR ASL | dst `[2:0]`; `[10]`=1: count = R`[7:5]` & 31, else imm5 `[9:5]` |
| `11 11 100 …` | MULS | `rd=[2:0] = R[5:3] * R[8:6]` (unsigned 32x32, low 32; V = high 32 ≠ 0) |
| `11 11 110 …` | `[3]`: MVFC / MVTC | coprocessor moves; no-ops (no coprocessor) |

Everything else is undecodable (MAME executes it as a NOP). The core raises a visible `illegal_op` flag and
counter and the simulation harness stops; it still executes it as a NOP so the behaviour matches MAME.

## Flags

* ADD/ADC/SUB/SBC/NEG/CMP and immediate forms: Z, S, C, V (C for SUB = borrow; formulas as MAME).
* AND/OR/XOR/TST(+I), EXTB/EXTS: Z, S only.
* ASR/LSR/ASL: Z, S, C (C = last bit shifted out), V cleared. Shift count 0 (corner case): MAME's C is
  `BIT(val, -1)` / `BIT(val, 32)`; with host shift-count masking this is bit 31 (ASR/LSR) / bit 0 (ASL). The
  reference model and RTL implement that.
* MULS: V only.

## Control flow and exceptions

* Branch/CALL target = address of the branch + 2 + 2·off. CALL pushes the return address (branch + 2).
* JR/CALLR jump to `R[n]` (n = `[3:0]`; n ≥ 8 is reported as illegal — MAME would read PC/SR/SP/ER).
* SWI n (only if ENI): push PC(next), push SR, clear ENI/E/M, PC = read32(4·(0x10+n)).
* IRQ (level, checked after every instruction when ENI is set): push PC(next), push SR, clear ENI/E/M;
  vector = 2 if AUT clear, else the acknowledge vector from the VRender0 interrupt controller
  (`(int_high << 5) | lowest pending source`). `PC = read32(4·vector)`.
* NMI (edge): vector 1, also clears the NMI flag. Not wired on the Crystal System.

## Memory accesses

Aligned 16/32-bit accesses are single bus cycles; unaligned 16-bit and 32-bit accesses are split into byte
accesses in ascending address order. Push decrements SP by 4 before each store; pop increments after each load.

## Usage by Crystal of Kings (first 60 s of attract, 858 M instructions)

Most frequent: LERI (25 %), CMPI, JNZ, ANDI, LDSU, LDI, POP, CALL, ADDI. Never used: ADCI, SBCI, ADC, SBC, TST,
JNV, JV, JP, JM, LDBSP, SWI, HALT. MVTC/MVFC appear a handful of times (BIOS). The core implements all of them
anyway and verifies them against the reference model with random tests.

## Timing

MAME master: 3 CPU clocks (42.95 MHz) per instruction regardless of opcode, i.e. 6 clk_sys. The RTL CPU paces
itself to the same average rate with a bounded credit counter, so memory stalls are caught up.
